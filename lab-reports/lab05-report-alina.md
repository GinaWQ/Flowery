# ЗВІТ
## з лабораторної роботи № 5
### Розробка REST API для вебпроєкту Flowery

### 1. Мета роботи

Ознайомитися з принципами створення REST API, навчитися реалізовувати обробку HTTP-запитів, передавати дані у форматі JSON, виконувати операції з базою даних SQLite та документувати API за допомогою Swagger.

### 2. Завдання роботи

1. Реалізувати REST API для керування клієнтами.
2. Реалізувати REST API для керування промокодами.
3. Забезпечити виконання операцій отримання, додавання, оновлення та видалення даних.
4. Реалізувати перевірку вхідних даних та обробку помилок.
5. Використати HTTP-статуси для позначення результатів запитів.
6. Створити документацію API за допомогою Swagger.
7. Перевірити працездатність реалізованих методів.

### 3. Використані технології

- Python — мова програмування.
- Flask — вебфреймворк для створення API.
- SQLite — система керування базою даних.
- JSON — формат передавання даних.
- Flasgger (Swagger) — документація та тестування API.
- Git та GitHub — контроль версій і командна робота.

### 4. Хід виконання роботи

#### 4.1. Реалізація API для керування клієнтами

Було реалізовано REST API для роботи з клієнтами магазину Flowery.

Реалізовані методи:

| HTTP-метод | Адреса | Призначення |
|---|---|---|
| GET | /api/v1/customers | Отримання списку клієнтів |
| GET | /api/v1/customers/{customer_id} | Отримання клієнта за ID |
| POST | /api/v1/customers | Додавання нового клієнта |
| PUT | /api/v1/customers/{customer_id} | Оновлення даних клієнта |
| DELETE | /api/v1/customers/{customer_id} | Видалення клієнта |

Дані клієнтів зберігаються в базі даних SQLite. Для передавання інформації використовується формат JSON.

Також реалізовано перевірку введених даних та обробку ситуацій, коли клієнта не знайдено або номер телефону вже використовується.

#### 4.2. Реалізація API для керування промокодами

Було реалізовано REST API для керування промокодами магазину.

Реалізовані методи:

| HTTP-метод | Адреса | Призначення |
|---|---|---|
| GET | /api/v1/promo | Отримання списку промокодів |
| GET | /api/v1/promo/{promo_id} | Отримання промокоду за ID |
| POST | /api/v1/promo | Створення нового промокоду |
| PATCH | /api/v1/promo/{promo_id} | Часткове оновлення промокоду |
| DELETE | /api/v1/promo/{promo_id} | Видалення промокоду |

Для промокодів реалізовано перевірку обов'язкових полів, відсотка знижки, мінімальної суми замовлення, статусу активності та дати завершення дії.

Також передбачено обробку помилок, зокрема повторного створення промокоду з однаковим кодом.

#### 4.3. Обробка помилок

Для API реалізовано перевірку вхідних даних та повернення відповідних HTTP-статусів.

Основні статуси:

- 200 — запит успішно виконано.
- 201 — новий запис створено.
- 204 — запис успішно видалено.
- 400 — помилка у вхідних даних.
- 404 — запис не знайдено.
- 409 — конфлікт даних, наприклад повторний номер телефону або код промокоду.

#### 4.4. Документація Swagger

Для документування API використано бібліотеку Flasgger.

Було додано описи методів, параметрів запитів та можливих відповідей сервера.

Документація доступна за адресою:

`http://127.0.0.1:5000/apidocs/`

У Swagger створено окремі розділи «Клієнти» та «Промокоди», у яких відображаються всі реалізовані методи API.

### 5. Тестування API

Для перевірки працездатності виконано тестові HTTP-запити за допомогою Flask Test Client.

Результати перевірки:

| Перевірка | Очікуваний статус | Результат |
|---|---:|---:|
| Отримання списку клієнтів | 200 | Успішно |
| Створення клієнта | 201 | Успішно |
| Оновлення клієнта | 200 | Успішно |
| Видалення клієнта | 204 | Успішно |
| Повторний номер телефону | 409 | Успішно |
| Отримання неіснуючого клієнта | 404 | Успішно |
| Отримання списку промокодів | 200 | Успішно |
| Створення промокоду | 201 | Успішно |
| Оновлення промокоду | 200 | Успішно |
| Видалення промокоду | 204 | Успішно |
| Некоректний відсоток знижки | 400 | Успішно |

Додатково перевірено доступність документації Swagger та отримання успішних відповідей від API клієнтів і промокодів.
