## 1. Тема роботи
Розробка REST API для управління товарами та замовленнями вебзастосунку **Flowery** (командна робота, роль учасника B).

## 2. Мета роботи
Реалізувати серверну логіку роботи зі статусами замовлень та складом, розробити REST API-ендпоинти для керування товарами (`CRUD`) і замовленнями, перевірити працездатність коду та застосунку, а також оформити зміни через систему контролю версій Git і Pull Request на GitHub[cite: 1].

## 3. Виконані завдання
У межах лабораторної роботи в окремій гілці `feature/api-products-orders` виконано такі завдання[cite: 1]:

* Реалізовано спільну бізнес-логіку керування статусами замовлень і повернення товарів на склад при скасуванні замовлення (`cancelled`) у модулі `services.py` (`ORDER_STATUSES`, `set_order_status`).
* Реалізовано CRUD-ендпоинти API товарів у `routes/api_products.py` із валідацією вхідних даних та обробкою HTTP-помилок (`400`, `404`, `409`)[cite: 1].
* Реалізовано ендпоинти API замовлень у `routes/api_orders.py` (отримання списку з фільтрацією за статусом, отримання деталей замовлення з переліком товарів `items`, зміна статусу замовлення)[cite: 1].
* Перевірено коректність синтаксису реалізованих модулів командою `python -m py_compile services.py routes\api_products.py routes\api_orders.py`[cite: 1].
* Запущено локальний сервер Flask (`python app.py`) та перевірено його доступність за адресою `http://127.0.0.1:5000`[cite: 1].
* Зафіксовано зміни в Git (коміт `f83c442`), виконано відправку гілки у віддалений репозиторій (`git push -u origin feature/api-products-orders`) та створено Pull Request на GitHub.

## 4. Опис реалізованих компонентів

### 4.1. `services.py`
Містить централізовану логіку роботи зі статусами замовлень (`ORDER_STATUSES`) та функцію `set_order_status(db, oid, status)`, яка оновлює статус замовлення та повертає кількість товарів на склад у разі скасування замовлення (`cancelled`).

### 4.2. `routes/api_products.py`
Визначає Blueprint `api_products_bp` (`url_prefix='/api/v1'`) та реалізує CRUD-операції над товарами:

| Метод | Маршрут | Призначення | Основні коди відповіді |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/v1/products` | Список активних товарів (з можливістю фільтрації за `category`) та `count` | `200` |
| `GET` | `/api/v1/products/<int:pid>` | Деталі активного товару за ID | `200`, `404` |
| `POST` | `/api/v1/products` | Створення нового товару з валідацією полів та заголовком `Location` | `201`, `400`, `409` |
| `PUT` | `/api/v1/products/<int:pid>` | Повне оновлення даних товару | `200`, `400`, `404`, `409` |
| `PATCH` | `/api/v1/products/<int:pid>` | Часткове оновлення полів товару (наприклад, `price`, `stock`) | `200`, `400`, `404`, `409` |
| `DELETE` | `/api/v1/products/<int:pid>` | Видалення товару | `204`, `404` |

### 4.3. `routes/api_orders.py`
Визначає Blueprint `api_orders_bp` (`url_prefix='/api/v1'`) та реалізує роботу із замовленнями:

| Метод | Маршрут | Призначення | Основні коди відповіді |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/v1/orders` | Список замовлень (новіші спочатку) з фільтрацією за `status` | `200`, `400` |
| `GET` | `/api/v1/orders/<int:oid>` | Деталі замовлення разом із переліком товарів `items` | `200`, `404` |
| `PATCH` | `/api/v1/orders/<int:oid>` | Зміна статусу замовлення через `set_order_status` | `200`, `400`, `404` |

## 5. Перевірка роботи та Git-робочий процес

* **Перевірка синтаксису та запуск:** виконано `python -m py_compile services.py routes\api_products.py routes\api_orders.py` без помилок та запущено сервер `python app.py` на `http://127.0.0.1:5000`[cite: 1].
* **Тестування API:** перевірено запити до `/api/v1/products` та `/api/v1/orders` (створення, читання, оновлення, видалення, валідація та зміна статусу замовлення).
* **Робота з Git і GitHub:** зміни закомічено у гілку `feature/api-products-orders` (`f83c442`), відправлено на `origin` та оформлено Pull Request.
